# ArtemisFinancialCS305
  Artemis Financial was a consulting company that develops individualized financial plans for its clients, including services related to savings, retirement, investments, and insurance. The company relied on a RESTful web application to communicate with users and manage sensitive financial data. The main issue they wanted addressed was identifying security vulnerabilities within their system and improving the overall security of their application to protect against threats such as man-in-the-middle attacks, insecure API endpoints, and outdated software dependencies.
One thing I did well during the vulnerability assessment was identifying key security risks through both manual review and attempted static testing. I was able to recognize issues related to input validation, lack of authentication on API endpoints, poor error handling, and missing encapsulation in the code. Coding securely is important because it protects sensitive data from unauthorized access and prevents potential cyberattacks. Strong software security adds value to a company by protecting its reputation, maintaining customer trust, and reducing the risk of financial and legal consequences.
  One of the more challenging parts of the vulnerability assessment was working with the dependency-check tool during static testing. I encountered errors that prevented the tool from generating a full report, which made it harder to identify vulnerabilities automatically. However, this challenge helped me better understand the importance of properly configuring tools and also reinforced the value of manually reviewing dependencies when automated tools fail.
  To increase layers of security, I focused on implementing input validation, recommending secure API practices such as authentication and authorization, and emphasizing the need for encryption to protect sensitive data in transit. I also identified the importance of upgrading outdated dependencies, such as older cryptographic libraries and framework versions. In the future, I would use tools like OWASP Dependency-Check, static code analysis tools, and vulnerability databases such as the National Vulnerability Database (NVD) to assess vulnerabilities and determine the best mitigation strategies.
To make sure the application remained functional and secure, I reviewed the code after identifying vulnerabilities and ensured that recommended changes would not break existing functionality. After refactoring, it is important to retest the application and review the code again to confirm that no new vulnerabilities were introduced. This process helps maintain both stability and security within the application.
  Throughout this project, I used resources such as the vulnerability assessment process flow diagram, secure coding practices, and dependency-check tools to guide my analysis. These tools and practices will be useful in future assignments and real-world scenarios because they provide a structured approach to identifying and addressing security risks.
  For future employers, I could present my Artemis Financial Vulnerability Assessment Report as an example of my ability to analyze a system, identify security vulnerabilities, and recommend solutions to improve software security. This project demonstrates my understanding of secure coding practices and my ability to apply them in a real-world scenario.
